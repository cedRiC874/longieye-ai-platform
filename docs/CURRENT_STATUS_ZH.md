# LongiEye 当前完成情况与上线准备

> 项目版本：v0.5.0
> 文档更新日期：2026-09-01
> 项目定位：隐私优先、非临床用途的纵向近视风险 AI 工程原型

## 1. 项目简介

LongiEye 将纵向近视风险建模思路整理成一套可运行、可测试、可审计的 AI 工程流程。目前系统能够处理两次随访的结构化数据，生成 OD/OS 双眼演示分数，并通过严格模型门禁、合成影像质量控制和安全回退机制展示模型服务工程能力。

公开 API 继续使用确定性合成数据和完全由代码生成的合成眼底图。项目另有一条隔离的 OLSM 公开真实队列评估路径，Git 只保存聚合验证结果；所有输出都不能用于诊断、筛查、治疗或其他临床决策。

## 3. 已完成的核心能力

### 3.1 数据合同与特征工程

- 建立 Y1/Y2 两次随访的严格数据结构。
- 固定随访间隔为 12 个月。
- 校验字段类型、合理范围、有限数值和 Y1/Y2 性别一致性。
- 缺失值不做无依据插补，而是直接拒绝推理。
- 禁止姓名、受试者编号、图像路径等直接标识信息进入 API。
- 实现固定顺序的 9 维特征：静态性别编码和 8 项 `Y2 - Y1` 变化量。
- 保持特征顺序、归一化参数和模型输入合同可审计。

### 3.2 合成模型训练与推理

- 使用纯 Python 确定性生成合成训练和验证数据。
- 分别训练 OD 和 OS 两个逻辑回归输出头。
- 两个输出头共享完整双眼结构化输入，但不声称是联合概率模型。
- 将合成模型保存为可审阅 JSON 工件。
- 在模型加载阶段校验：
  - 特征顺序
  - 归一化向量长度与有效性
  - 模型系数、截距和有限数值
  - 模型阶段、训练来源与非临床标记
- 对相同输入提供确定性演示输出。

### 3.3 FastAPI 服务

- 提供 `/health`、`/ready` 和 `/predict` 端点。
- 提供中文 OpenAPI 接口说明和 Swagger 页面。
- 使用严格请求模型，拒绝额外字段、错误类型和不完整输入。
- 使用稳定错误码和非回显错误消息。
- 实现端到端请求 ID。
- 实现隐私安全的结构化 JSON 日志，不记录请求正文或查询参数。
- 公开 `/predict` 始终固定使用 `demo_synthetic` 模型，不能通过环境变量静默切换到研究模型。

### 3.4 研究模型接入门禁 Phase A

- 抽象 `RiskModelBackend`，使服务逻辑不依赖具体模型类。
- 实现 `ResearchModelAdapter` 和版本化研究 manifest 合同。
- 使用包外审批回执，模型包不能自行声明“已经批准”。
- 将审批请求绑定到：
  - 来源 commit
  - checkpoint SHA-256
  - 预处理摘要
  - 模型卡摘要
  - 黄金向量摘要
  - 完整 manifest 与加载器合同
- 严格检查研究模型包文件清单、普通文件类型、大小限制和符号链接。
- 在反序列化前校验模型工件 SHA-256。
- PyTorch 路径使用 CPU、`weights_only=True`、`eval()` 和 `inference_mode()`。
- 校验 state dict 的精确 key、shape、dtype 和有限数值。
- 通过多组黄金向量验证确定性和 OD/OS 数值兼容性。
- 预测与 readiness 阶段能够重新检查审批有效期、撤销状态和内存参数完整性。
- 任一步失败都会拒绝构造或锁定为 `not_ready`，不会回退到其他模型继续输出。

当前公开仓库没有真实研究 checkpoint、真实预处理统计、逐人预测或 OOF 输出。Phase A 只证明模型接入边界，不能证明真实研究模型已经成功转换或具有临床性能。

### 3.5 全合成多模态路径 Sprint 3A

- 使用固定整数绘图规则生成两张 128 x 128 OD/OS 合成眼底示意图。
- 图像带有明显的 `SYNTHETIC OD/OS` 水印。
- 生成过程不读取真实图像、不使用生成模型或医学图像数据集。
- 实现严格 canonical PNG 解码：
  - 固定 RGB8 格式和尺寸
  - 固定 chunk 顺序
  - CRC 校验
  - 有界解压
  - 禁止元数据与尾随内容
- 使用文件和像素 SHA-256 将固定 fixture 与 OD/OS 眼别绑定。
- 实现亮度、对比度、裁剪比例、视野覆盖和清晰度质量门。
- 实现确定性的 32 x 32 预处理和 5 维可解释图像统计编码。
- 以结构化分数为锚点，在 logit 层增加最大绝对值为 `0.35` 的逐眼修正。
- 图像缺失、质控失败或编码器不可用时，对应眼精确回退到结构化分数。
- 眼别、来源或摘要冲突时整单 fail-closed。
- 输出分支模式和安全原因码，不输出图像路径、哈希、像素、embedding 或内部异常。

当前多模态路径仅供离线演示，不接入公开 HTTP，不读取任意外部图片，也不证明 CNN、多模态增益或真实图像有效性。

### 3.6 OLSM 公开纵向结局验证

- 该实验验证的是评估管线，不是 LongiEye 的 Y1→Y2 变化量模型；任务属于基线预测因子到五年结局的预后建模，而非纵向轨迹建模。
- 使用 Orinda Longitudinal Study of Myopia 的公开子集。
- 618 名基线非近视儿童，五年内新发近视 81 例。
- 固定源 commit、文件 SHA-256 和 18 列数据合同。
- 原始逐人行仅下载到忽略的本地 `build/`，不进入 Git。
- 三个在本分析版本中定义的 ridge 逻辑回归模型使用重复嵌套 5×5 participant-level cross-fitting；方案没有独立预注册。
- 所有 AUC、Brier、BSS、校准和 DCA 都基于每名参与者 5 份重复 OOF 概率的平均值。
- 使用 2,000 次参与者 bootstrap 计算条件于重复 OOF 预测的区间；不把它描述为整条流水线重拟合区间。
- 输出校准截距、校准斜率、校准曲线和探索性 DCA。
- 三个配对 AUC 比较使用 Holm 方法控制 FWER 0.05。
- 事件率常数模型 Brier 为 `0.114`；完整模型 AUC 为 `0.872`（95% CI `0.830-0.911`），Brier 为 `0.080`（`0.066-0.096`），BSS 为约 `0.30`。
- 三项 Holm 调整后 p 值均为 `1.000`，没有证据表明复杂模型优于简单模型。
- 单一基线屈光度已经获得 AUC `0.859`，说明另外 13 个特征没有提供统计上可确认的增量；这支持低成本筛查假设，但不是临床建议。

该公开子集包含基线右眼预测变量和五年纵向结局，但没有重复 Y1/Y2 预测变量。因此它不复现原九维变化量模型，也不验证当前合成 API。完整模型 81 个事件对应 14 个特征，名义 EPV 约 `5.8`，低于传统经验阈值 10；ridge 只能缓解而不能消除过拟合风险。由于没有外部队列，结果只能称为 pilot 内部验证。

`aplore3` 分发包的 GPL-3 已确认，但底层 OLSM 队列数据的再利用权未由本项目独立核验。Git 只保存聚合结果和曲线，冻结模型参数留在本地忽略目录；公开模型参数或商业使用前仍需人工权利审查。

## 4. 工程质量与验证证据

### 4.1 测试与持续集成

- 当前完整测试基线：`155 passed`。
- 默认轻量环境：`141 passed, 6 skipped`，跳过可选 PyTorch 和公开队列专项模块。
- GitHub Actions 独立安装 CPU-only PyTorch，并强制研究 adapter 测试真实运行。
- Ubuntu 覆盖 Python 3.10、3.11 和 3.12。
- Windows Python 3.12 验证模型与图像工件跨平台确定性。
- wheel 在隔离环境中安装并执行导入和版本 smoke test。
- CI 检查公开仓库和构建上下文，降低真实数据、模型权重和未授权影像误提交风险。

失败路径测试覆盖：

- 缺失或额外字段、错误类型和越界值
- 错误特征顺序和归一化配置
- checkpoint 摘要不匹配
- 权重 key、shape、dtype 和 NaN/Inf 错误
- 审批回执缺失、过期、撤销或内容不匹配
- 额外文件、超限文件和符号链接
- 黄金向量输出不匹配
- PNG CRC、chunk、尺寸、解压和尾随内容错误
- 图像眼别、来源、摘要和质量门错误
- 编码器不可用、异常输出和运行时参数变化

### 4.2 可复现性

- 固定 Python 依赖锁文件。
- 支持 Python 3.10 到 3.12。
- 使用 `timezone.utc` 保持 Python 3.10 兼容性。
- 锁定兼容 Python 3.10 的 `websockets 16.1.1`。
- 仅在模型工件发布边界将浮点数规范化为 12 位有效数字。
- 固定 UTF-8、LF 和 JSON 序列化规则。
- 重新训练后通过 Git diff 检查模型工件是否确定。
- 合成眼底 fixture 可由脚本重新生成并逐字节校验。
- 发布前检查 wheel 是否包含最新源码，避免上传陈旧构建。

### 4.3 基准

结构化合成模型已有本机顺序基准，包括核心服务和进程内 ASGI 的 P50、P95、P99、顺序吞吐量及内存指标。

合成多模态路径已分别测量：

- 双眼图像可用
- 缺失 OS
- 双眼缺失并回退

多模态双眼场景的已记录 P95 为约 `55.3 ms`。该结果来自单进程顺序离线基准，包含质量门、预处理、统计编码和融合，但不包含文件读取、HTTP、网络、容器或并发负载，因此不能作为线上 SLA。

## 6. 当前可以用它做什么

目前可以安全地把 LongiEye 用于：

- AI 工程师求职作品集展示。
- 演示严格数据合同与错误边界。
- 演示可复现的合成训练、工件生成和推理服务。
- 演示研究模型的授权、完整性和数值兼容性门禁设计。
- 演示合成图像质量控制、多模态接口和安全回退。
- 展示公开真实队列上的嵌套交叉验证、bootstrap 区间、校准、探索性 DCA 和多重性校正。
- 演示 FastAPI、Docker、CI/CD、日志、测试与工程文档能力。
- 讨论医疗 AI 中工程正确性、模型有效性和临床证据之间的区别。

目前不能将它用于：

- 真实患者风险评估。
- 医疗诊断、筛查或治疗建议。
- 证明真实世界模型性能。
- 上传或处理真实眼底图。
- 公开发布未授权研究 checkpoint 或统计信息。
- 宣称符合医疗法规或已经达到生产临床标准。

## 7. 上线作品集 Demo 仍需完成

代码已经具备可部署基础，但真正开放公网前仍建议完成：

1. 选择云服务器或容器部署平台。
2. 配置正式域名和 HTTPS。
3. 增加身份认证、访问控制和速率限制。
4. 根据前端来源配置严格 CORS。
5. 配置生产日志、监控、告警和健康检查。
6. 完成并发 1、8、32 等负载下的 P50/P95/P99、吞吐和资源测试。
7. 配置备份、故障恢复、版本回滚和事件响应流程。
8. 在页面和响应中持续展示“合成数据、非临床用途”免责声明。
9. 检查演示录屏和线上页面，确保没有私有桌面信息或环境变量泄漏。

作品集 Demo 上线后，仍只能称为工程演示服务，不能称为临床产品。

## 8. 接入真实数据或临床使用仍需完成

真实研究和临床化的最大差距不是部署服务器，而是授权数据、临床证据与治理责任链。至少需要：

- 取得数据所有权、伦理、知情同意和机构审批。
- 明确 intended use、目标标签、预测时点和临床工作流。
- 在受控环境中完成真实模型和预处理导出。
- 采用参与者级拆分，避免左右眼和多次随访数据泄漏。
- 完成时间外、院外和多设备外部验证。
- 报告区分度、Brier score、校准曲线、置信区间和亚组表现。
- 评估非随机缺失、测量误差、标签噪声、设备偏移和时间漂移。
- 为结构化、融合和回退路径分别进行校准与不确定性评估。
- 完成前瞻性 shadow evaluation，再决定是否进入临床工作流。
- 建立加密、访问控制、持久审计、数据保留、撤销、监控和安全回滚。
- 由临床、伦理、隐私、信息安全和合规负责人共同确认监管路径。

## 9. 当前结论

LongiEye v0.5.0 已经完成一条较完整的非临床 AI 工程链路：严格结构化输入、确定性合成服务、研究模型 fail-closed 门禁、全合成图像质量控制、结构化锚定融合、逐眼精确回退，以及隔离的 OLSM 真实公开队列内部验证、跨版本测试、容器与 CI。

项目当前最适合用于求职作品集和工程能力展示。它证明了如何可靠、可审计地接入和运行模型，但没有证明模型可以用于真实医疗决策。若仅上线作品集 Demo，主要工作是生产部署与运维加固；若要接入真实患者数据，主要工作则是数据授权、模型验证、临床证据和合规治理。
