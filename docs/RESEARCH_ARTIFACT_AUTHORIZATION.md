## 机器授权合同

研究包内的 manifest **只能提出授权请求，不能声明自己已获批准**。它记录一个非敏感 `reference_id` 和当前唯一受支持的请求范围 `local_adapter_evaluation`。加载器还必须从包外取得 `ApprovalPolicy` 返回的审批回执；没有外部策略或回执时一律拒绝。

审批回执绑定一个规范化 request SHA-256，该请求同时覆盖：

- reference ID 与用途范围；
- model ID 与私有来源 commit；
- checkpoint、预处理统计、模型卡和黄金向量各自的 SHA-256。
- 完整规范化 manifest 的 SHA-256 与 loader 合同版本，避免其他元数据或合同升级绕过旧回执。

回执还包含 receipt ID、签发时间、到期时间和撤销状态。加载时会核对 scope、request hash、有效期和撤销状态；回执文件不得位于研究包内。当前代码只验证回执位于包外及其内容绑定，不检查文件 ACL、所有者或审批方身份。部署方必须在代码之外建立受控目录和访问权限；`ExternalJsonApprovalPolicy` 不是数字签名或机构身份认证。若未来需要公开发布，应由机构控制的签名服务或审批存储实现同一 `ApprovalPolicy` 接口。

Adapter 每次推理都会重新检查已加载回执是否过期；每次 `readiness()` 还会向外部 policy 重新取回同一回执，以发现撤销或内容替换。一旦失败，实例保持 `not_ready`，必须完成重新审批并重新加载，不能在原实例上静默续期。

内部 `_TorchStateDictRuntime` 不提供公开 raw-bytes factory，只接受本模块产生的已验证包结果。这能阻止正常 API 的意外绕过，但 Python 的下划线、构造 token 和私有属性不是针对同进程恶意代码的安全沙箱；研究进程必须只运行受信任代码，强隔离需求应使用受限子进程或容器边界。

## 工件范围

“研究工件”包括但不限于：

- PyTorch checkpoint、state dict、TorchScript、ONNX、safetensors 或其他权重文件；
- 特征均值、标准差、归一化参数、类别映射和校准参数；
- 训练、验证或测试拆分 ID；
- 参与者级标签、预测、OOF 输出、嵌入或缓存；
- 原始或衍生临床表格、眼底图像、图像路径、哈希与文件名；
- 训练配置、日志或报告中可能暴露个人数据、私有路径、凭证或受限数据统计的内容。

## Gate A：所有权与研究治理

- [ ] 已确认代码、模型权重、预处理统计和聚合结果分别由谁拥有。
- [ ] 已确认学校、实验室、导师、合作机构和资助协议对复制、演示和发布的要求。
- [ ] 已核对伦理审批、知情同意和数据使用协议是否覆盖模型导出与二次展示。
- [ ] 已明确“仅本地评估”“向招聘方演示”和“公开发布”是否需要不同批准。
- [ ] 已记录批准人、批准日期、批准范围和到期/撤销条件。
- [ ] 已固定来源仓库 commit，并确认工作区没有混入未经审查的后续文件。

## Gate B：隐私与安全审查

- [ ] 工件不含姓名、证件号、联系方式、受试者编号或可重识别自由文本。
- [ ] 工件不含参与者级输入、标签、拆分、预测、OOF 输出或嵌入。
- [ ] 工件不含本地绝对路径、用户名、服务器地址、访问令牌、密钥或连接字符串。
- [ ] 已评估 checkpoint、预处理统计和小样本聚合值的隐私泄露风险。
- [ ] 已使用明确的 allowlist 构建导出包，而不是复制整个研究目录后再删除文件。
- [ ] 已检查 Git 历史、CI artifact、cache、镜像层和 Release，而不只是当前工作树。
- [ ] 真实工件只存放在批准的隔离位置，公开测试使用完全合成 fixture。
- [ ] 只加载来源可信且明确获批的 checkpoint；`weights_only=True` 与文件大小上限会收窄风险，但不是反序列化沙箱，也不能完全阻止拒绝服务或内存耗尽。

## Gate C：工程与可追溯性

- [ ] manifest 记录 schema、特征契约、框架版本、shape、dtype 和来源 commit。
- [ ] manifest 记录 artifact SHA-256、预处理统计 SHA-256 和模型卡路径。
- [ ] 包外审批回执绑定 artifact、预处理、模型卡、黄金向量和来源 commit，并记录 scope、签发/到期时间与撤销状态。
- [ ] adapter 在 `eval`/inference 模式运行，并校验输入、输出、NaN/Inf 和眼别顺序。
- [ ] golden vectors 与 parity report 能将导出前后的差异限定在预先声明的容差内。
- [ ] 错误 checksum、未知 schema、特征顺序不一致、错误 shape/dtype 或未批准 stage 均 fail closed。
- [ ] comparison report 仅保存获批范围内的工程合同与运行证据；合成指标和研究指标保持独立且默认不包含。
- [ ] 已记录回滚方式；载入失败时不会静默回退为另一模型并继续输出难以辨认的结果。

## Gate D：指标与模型卡

- [ ] 每个研究数字都映射到固定 commit、聚合结果文件、计算脚本和论文表格。
- [ ] 样本量、事件数、纳排标准、预测目标、验证设计和置信区间均已核对。
- [ ] 不同队列、模态、消融实验和重复交叉验证结果使用不同实验 ID。
- [ ] 合成 AUC 不与研究 AUC 同表比较，也不作为医疗效果或简历成果。
- [ ] 已填写研究模型卡，并清楚说明内部验证、外部验证、校准和亚组分析状态。
- [ ] 简历措辞已由原始聚合证据复核，不把 adapter 验证写成模型效果提升。

## Gate E：决定与加载映射

只有前述 Gate 全部完成后，批准人才能作出决定。治理记录中的 `not_reviewed` 或 `rejected` 均不签发可用回执，加载器保持关闭；这些是人类审批决定，不是 manifest 可自行填写的加载状态。`approved_for_local_use` 可以签发 scope 为 `local_adapter_evaluation` 的限时包外回执，只允许指定私有环境中的离线验证。

公开发布必须另有明确的 release 决定，绑定确切工件与材料哈希；当前 v1 loader 不把“本地可加载”解释为“可公开发布”。对某一版本的批准不自动覆盖重新训练、重新导出或修改后的工件。

## SHA-256 的含义

SHA-256 用于检测“当前文件是否与已审查文件逐字节一致”，即完整性校验。它不证明：

- 谁创建或批准了该工件；
- 工件来源是否可信；
- 工件不包含恶意内容或隐私信息；
- 工件具有临床有效性；
- 工件获得了公开发布授权。

除非另有可验证的数字签名、可信密钥管理和批准记录，否则不得把 SHA-256 描述为“签名”“认证”或“可信发布”。
